# 運用マニュアル（日本語） — moodle-grading-mcp

**対象読者：本サーバを使って Moodle を操作する運用担当者**
（エンジニアでなくても導入できるように書いています）

---

## 0. まず結論（3行）

1. このMCPサーバを入れると、**Claude（AI）に日本語で頼むだけで Moodle のコース構成・課題・提出物を調べられる**ようになります。Moodleの管理画面を何十回もクリックする作業が要りません。
2. **書き込みは「採点ドラフトの保存」1種類だけ**です。しかも初期状態では書き込み自体が無効で、有効化しても許可したコース以外には一切書けません。**成績の公開（受講生への開示）はこのツールでは絶対にできません。**
3. **導入する人は「自分のMoodleアカウントで自分専用のトークン」を発行してください。** 他人のトークンを使い回すと、Moodleの操作ログ上はトークンの持ち主が操作したことになります（→ 第8章）。

---

## 1. このツールは何か

Moodle には「Web Services（外部連携API）」という公式の窓口があります。このリポジトリの `server.py` は、その窓口を **MCP（Model Context Protocol）** という規格に変換して、Claude などのAIクライアントから使えるようにする小さなサーバです。

```
  あなた
    │  「2026年のレポート提出コースで、採点待ちの人を出して」
    ▼
  Claude（Claude Code / Claude Desktop）
    │  MCP
    ▼
  moodle-grading-mcp（server.py）  ← 安全規則はここで強制される
    │  Moodle Web Services (REST)
    ▼
  Moodle サイト
```

重要な設計思想：**このサーバは「採点の判断」を一切持ちません。** 点数を決めるのはAI（＋あなたの採点基準プロンプト）で、サーバは「提出物を取ってくる」「採点を未公開ドラフトで書き込む」という入出力だけを担当します。だからこそ、危険な操作をサーバ側で機械的に禁止できます。

## 2. できること（ツール7種）

AIに日本語で頼めば、AIが適切なツールを選んで実行します。ツール名を覚える必要はありませんが、「何ができるか」の範囲は把握しておいてください。

| # | ツール | できること | 使いどころ |
|---|---|---|---|
| 1 | `verify` | 接続確認。サイト名・ログイン中のユーザ名・利用可能な関数数・書き込み設定を返す | 導入直後の動作確認。トラブル時の切り分け |
| 2 | `find_courses` | 閲覧可能なコースの一覧（ID・略称・正式名・カテゴリ・公開状態）。`name_like` でキーワード絞り込み（空白区切りの全語AND部分一致） | 「2026年の上級コースのIDは？」を調べる起点 |
| 3 | `course_contents` | コースの週次セクションと、各回の教材モジュール一覧（種別・名称・URL・添付ファイル名） | **カリキュラム棚卸し。年度間の構成比較。教材の抜け漏れチェック** |
| 4 | `list_assignments` | コース内の課題一覧（課題ID・cmid・名称・締切・満点） | 課題の満点設定や締切の一覧確認 |
| 5 | `list_pending` | 提出済みかつ未採点の提出一覧（ユーザID・提出日時・提出ID） | 採点待ち残数の把握。二重採点の防止 |
| 6 | `get_submission` | 指定受講生の提出内容（オンラインテキスト本文・添付ファイル**名**・提出状態・採点状態） | 個別の提出内容の確認 |
| 7 | `save_grade_draft` | **採点を「未公開ドラフト」で書き込む（唯一の書き込みツール）** | AI採点ドラフトの作成。人が確認して公開 |

### 使い方のイメージ（そのままAIに投げてOK）

- 「moodle-grading で接続確認して」
- 「`name_like` に "2026 春" を入れてコースを探して、IDと正式名だけ表で出して」
- 「コース<ID>の課題を一覧にして。満点も出して」
- 「コース<ID>のセクション構成を出して。各回の教材の種別と名前を箇条書きで」
- 「コース<ID>の課題<課題ID>で採点待ちの人数を教えて」
- 「昨年度と今年度のコースのセクション構成を並べて、増えた教材・消えた教材を比較して」

## 3. できないこと（重要・誤解が多い箇所）

このMCPサーバに **ツールが存在しない＝絶対にできない** ことです。

| できないこと | 補足 |
|---|---|
| **成績の公開（release）** | `save_grade_draft` は `workflowstate=readyforreview`（採点済み・未公開）で固定。コードレベルで `released` にする経路がありません。公開は人がMoodle画面で行います |
| **受講生への通知メール送信** | ドラフト状態のためMoodleは通知を出しません |
| **コースの作成・複製・編集** | 教材の追加・差し替え・並べ替えはできません。Moodle画面で行ってください |
| **教材ファイルのアップロード／ダウンロード** | `course_contents` はファイル**名とURL**を返すだけで、中身は取得しません |
| **提出された添付ファイルの中身を読む** | `get_submission` が返すのはファイル**名**のみ。PDF・Word・Excelの中身は読めません（→ 第9章の注意） |
| **受講生の登録・削除・グループ分け** | 受講管理の操作は一切ありません |
| **小テスト（quiz）の設問取得・採点** | 対応していません。対象は「課題（assign）」のみ |
| **受講生の氏名・メールアドレスの取得** | 返るのは数値の `userid` だけです（個人情報の取り扱いを最小化する設計） |
| **バッジ・修了証の発行** | ありません |

## 4. 導入手順（初回のみ・30分程度）

### 4-1. 用意するもの

- **PC**（macOS / Windows / Linux）
- **Python 3.10 以上**
  - 確認：ターミナル（Windowsはコマンドプロンプト）で `python3 --version`
- **Moodleの採点権限を持つアカウント**（＝対象コースの教師権限など）
- **Claude Code**（ターミナル版）または **Claude Desktop**

### 4-2. Moodleトークンを発行する

**必ず自分自身のアカウントで発行してください。**

1. Moodle にログイン
2. サイト管理 → サーバー → Web サービス → **トークンの管理**
3. 「トークンを追加する」→ ユーザ＝自分、サービス＝採点用に用意されたサービスを選択
4. 表示された長い英数字（トークン）を控える

> **トークンは実質パスワードです。** Slack・メール・Googleドキュメント等に貼らないでください。紛失・漏洩の疑いがあれば同じ画面で即座に削除できます。
> サービスに許可が必要な関数は **付録A** を参照。Web Services が無効なサイトでは、まず「サイト管理 → 詳細設定 → Webサービスを有効にする」が必要です。

### 4-3. ファイルの取得と依存関係のインストール

```bash
git clone <このリポジトリのURL>
cd moodle-grading-mcp
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Windows（PowerShell）の場合：

```powershell
git clone <このリポジトリのURL>
cd moodle-grading-mcp
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

### 4-4. `.env` を作る（置き場所に注意）

> **⚠️ ここが一番つまずきます。**
> `server.py` は **`server.py` の 1つ上の階層** にある `.env` を読みます（コード：`load_dotenv(os.path.join(_HERE, "..", ".env"))`）。
> つまり `moodle-grading-mcp/.env` **ではなく**、`moodle-grading-mcp` と同じ並び（親フォルダ直下）の `.env` です。

```
親フォルダ/
├── .env                 ← ここに置く
└── moodle-grading-mcp/
    ├── server.py
    └── ...
```

`.env` の中身：

```sh
MOODLE_URL="https://<Moodleのドメイン>"
MOODLE_TOKEN="<4-2で発行したトークン>"
MOODLE_ALLOW_WRITE=0                 # 0=読み取り専用（推奨の初期値）
MOODLE_WRITE_COURSE_ALLOWLIST=       # 書き込みを許すコースID（カンマ区切り／空=どこにも書けない）
```

`.env` を作らず、シェルの環境変数として `export` しても動きます。どちらでも構いません。

### 4-5. Claude に登録する

**Claude Code の場合** — プロジェクト直下に `.mcp.json` を作成：

```json
{
  "mcpServers": {
    "moodle-grading": {
      "command": "/絶対パス/moodle-grading-mcp/.venv/bin/python",
      "args": ["/絶対パス/moodle-grading-mcp/server.py"]
    }
  }
}
```

**Claude Desktop の場合** — 設定 → 開発者 → 構成ファイルを編集 で、上と同じ `mcpServers` ブロックを追記。

いずれも **絶対パス** で書き、保存後にクライアントを再起動してください。

### 4-6. 動作確認

Claude に次のように頼みます。

> 「moodle-grading の verify を実行して」

こう返れば成功です（例）：

```json
{
  "site": "（あなたのMoodleサイト名）",
  "user": "（あなたの氏名）",
  "functions": 46,   // サイトにより異なる
  "allow_write": false,
  "write_courses": []
}
```

- `user` が **自分の氏名** になっているか必ず確認してください（→ 第8章）
- `allow_write: false` は正常です。読み取りはこの状態で全て使えます

## 5. 日常の使い方

### 5-1. 教材構成の棚卸し（棚卸し用途）

```
1) find_courses で年度・キーワードからコースIDを引く
2) course_contents でセクション（各回）と教材モジュールを一覧化
3) 必要なら list_assignments で課題の満点・締切を確認
```

AIへの依頼例：

> 「moodle-grading で、name_like に "2026 オンライン" を指定してコースを探して。
> 見つかったコースの course_contents を取って、セクション名と各セクションの教材を
> 種別（動画/資料/課題）ごとに整理した表にして。」

> 「昨年度のコース（ID=<旧>）と今年度のコース（ID=<新>）の構成を比較して。
> セクション単位で、追加された教材・削除された教材・名称が変わった教材を出して。」

### 5-2. 採点待ちの確認（読み取りのみ・安全）

> 「コース<ID>の課題<課題ID>で、採点待ちの件数を出して」

`list_pending` は「提出済み **かつ** まだ評点が付いていない」ものだけを返します。自分が入れたドラフトも「評点あり」として除外されるので、**同じ人を二重に採点することがありません**。

### 5-3. 採点ドラフトを書く（書き込みを解禁する手順）

書き込みには **2つの鍵** が両方必要です。片方だけでは書けません。

1. `.env` の `MOODLE_ALLOW_WRITE=1`
2. `.env` の `MOODLE_WRITE_COURSE_ALLOWLIST` に **対象コースIDを明記**

```sh
MOODLE_ALLOW_WRITE=1
MOODLE_WRITE_COURSE_ALLOWLIST=<書き込みを許すコースID>
```

変更したら Claude（クライアント）を再起動 → `verify` で `allow_write: true` / `write_courses: ["<コースID>"]` を確認。

**推奨運用：**
- まず本番ではないテスト用コースIDだけを allowlist に入れて試す
- 本番コースを入れるのは、採点基準（ルーブリック）が確定してから
- 採点が終わったら **`MOODLE_ALLOW_WRITE=0` に戻す**（事故防止）

採点の流れ：

```
list_pending → get_submission → （AIがあなたの採点基準で採点） → save_grade_draft
                                                                      ↓
                                          Moodle画面で人が確認 → 公開（release）
```

採点基準は `prompts/example_grade_prompt.md` を雛形に、**運用チームで定めたルーブリックを書き込んで**使ってください。サンプルには意図的に採点基準が入っていません（基準は運用側が決めるべきものだからです）。

### 5-4. 毎日の自動採点（任意・上級者向け）

`run_daily_grade.sh` を cron に登録すると、毎日決まった時刻に「採点待ちを拾って採点ドラフトを作る」処理を回せます。

```bash
GRADE_COURSE=<コースID> ./run_daily_grade.sh
```

環境変数：`GRADE_COURSE`（必須・コースID）、`GRADE_PROMPT`（採点プロンプトのパス）、`LLM_CLI`（既定 `claude`）。実行ログは `grade.log` に追記されます。**この場合も公開は行われません。**

## 6. 安全設計（サーバ側で強制される4つの規則）

`save_grade_draft` を呼ぶと、AIが何を指示されようと以下が機械的に適用されます。設定で緩めることはできません。

| 規則 | 内容 |
|---|---|
| **未公開の固定** | `workflowstate=readyforreview`（採点済み・未公開）で書き込み。`released` にする経路がコード上に存在しない |
| **通知なし** | ドラフト状態のため、Moodleは受講生に通知しません |
| **AI開示フッターの自動付与** | 講評に「AI-assisted grading」の文言が無ければ、AI支援採点である旨の開示文を自動で追記。文面は `MOODLE_AI_FOOTER_FILE` で差し替え可能 |
| **コース許可リスト** | `MOODLE_WRITE_COURSE_ALLOWLIST` に無いコースIDへの書き込みは拒否。空なら**どこにも書けない** |

### 監査ログ

書き込みの **試行・拒否・成功のすべて** が JSONL 形式で `audit.log`（既定：`server.py` と同じフォルダ）に追記されます。記録されるのは日時・イベント種別・実行主体・トークンの**末尾4桁のみ**・コースID・課題ID・ユーザID・点数など。トークン本体は記録されません。

`.env` と `*.log`（`audit.log` を含む）は `.gitignore` 済みです。**トークンを Git にコミットしないでください。**

## 7. 「誰の名義で操作しているか」の注意 ★最重要

MCPサーバは `.env` の `MOODLE_TOKEN` を使って Moodle にアクセスします。**Moodleから見れば、操作しているのはそのトークンの持ち主です。**

したがって：

- ✅ **正しい運用**：利用者それぞれが、**自分のMoodleアカウントで自分のトークンを発行**し、自分の `.env` に設定する。誰が何をしたかがMoodleの操作ログと `audit.log` の両方で追える。
- ❌ **避けるべき運用**：1つのトークンを複数人で共有する。Moodleのログ上は全員が同一人物として記録され、**誤った採点や誤操作があっても誰の操作か特定できません**。また、トークンの持ち主に権限のある範囲すべてが、共有相手にも開放されます。

また、標準の stdio 接続では `audit.log` の実行主体は `local` と記録されます（PCローカルで動いているため）。**「誰が採点したか」の区別は、実質的にトークンの発行単位で決まります。**

サーバをHTTPで公開して複数人で共有する構成（`MCP_TRANSPORT=streamable-http` + `MCP_BEARER_TOKENS`）も実装されていますが、**成績書き込みAPIをネットワークに露出させることになるため、通常の利用では推奨しません。** 各自ローカルで動かしてください。

## 8. トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| `.env の MOODLE_URL / MOODLE_TOKEN が未設定です` | `.env` の置き場所が違います。**`server.py` の1つ上の階層**に置いてください（→ 4-4） |
| `Moodle error [invalidtoken]` | トークンが誤っている／失効している。Moodleでトークンを再発行 |
| `Moodle error [accessexception]` 等 | そのWeb Service関数がサービスに許可されていない（→ 付録A）、またはアカウントに権限が無い |
| Claudeにツールが出てこない | `.mcp.json` のパスが絶対パスか確認 → クライアントを再起動 |
| `write disabled` エラー | `MOODLE_ALLOW_WRITE=1` になっていない。設定後に再起動 |
| `course XXX は書込許可リストに含まれません` | `MOODLE_WRITE_COURSE_ALLOWLIST` にそのコースIDを追加（本番保護の意図的な挙動） |
| 課題IDを指定したのに空が返る | `cmid`（コースモジュールID）と `id`（課題インスタンスID）を取り違えています。**採点で使うのは `id`** |
| 提出ファイルの中身を読ませたい | このツールでは取得できません。Moodle画面からダウンロードして、Claudeに直接添付してください |
| `find_courses` の結果が多すぎる | `name_like` にキーワードを複数入れる（空白区切りの全語AND部分一致）。例：`name_like="2026 春 レポート"` |

## 付録A：サービスに許可が必要な Web Service 関数

| 関数 | 用途 | 種別 |
|---|---|---|
| `core_webservice_get_site_info` | 接続確認 | 読み取り |
| `core_course_get_courses_by_field` | コース検索 | 読み取り |
| `core_course_get_contents` | コース構成の取得 | 読み取り |
| `mod_assign_get_assignments` | 課題一覧 | 読み取り |
| `mod_assign_get_submissions` | 提出一覧 | 読み取り |
| `mod_assign_get_grades` | 既存評点の取得（未採点判定用） | 読み取り |
| `mod_assign_get_submission_status` | 個別の提出内容 | 読み取り |
| `mod_assign_save_grade` | 採点ドラフトの保存 | **書き込み** |

読み取りのみで運用する場合、最後の `mod_assign_save_grade` はサービスから外して構いません。**それが最も安全な構成です。**

## 付録B：環境変数一覧

| 変数 | 既定値 | 説明 |
|---|---|---|
| `MOODLE_URL` | （必須） | MoodleサイトのURL |
| `MOODLE_TOKEN` | （必須） | Web Servicesトークン |
| `MOODLE_ALLOW_WRITE` | `0` | `1` で書き込み有効 |
| `MOODLE_WRITE_COURSE_ALLOWLIST` | 空 | 書き込みを許すコースID（カンマ区切り）。空＝どこにも書けない |
| `MOODLE_AI_FOOTER_FILE` | 空 | AI開示フッターを差し替えるHTMLファイルのパス |
| `MOODLE_AI_FOOTER_MARK` | `AI-assisted grading` | フッター有無の判定に使う語。フッター文面に必ず含めること |
| `MOODLE_AUDIT_LOG` | `server.py と同じフォルダ/audit.log` | 監査ログの出力先 |
| `MOODLE_LOG_LEVEL` | `INFO` | ログレベル |
| `MCP_TRANSPORT` | `stdio` | `streamable-http` / `sse` も選択可（通常は変更不要） |
| `MCP_BEARER_TOKENS` | 空 | HTTP公開時のBearer認証トークン（カンマ区切り）。**HTTP公開するなら必須** |
| `MCP_HOST` / `MCP_PORT` | 空 | HTTP公開時の待受先 |

## 付録C：推奨運用ルール（たたき台）

1. **各自が自分のトークンを発行する。** トークンの共有は禁止。
2. **既定は読み取り専用。** `MOODLE_ALLOW_WRITE=0` を平時の状態とする。
3. **書き込みを行う日は、対象コースIDだけを allowlist に入れ、終わったら 0 に戻す。**
4. **AI採点ドラフトは必ず人が確認してから公開する。** 公開操作はMoodle画面で行い、AIには行わせない。
5. **採点基準（ルーブリック）は運用チームで合意した版をプロンプトに明記する。** 個人が勝手に変えない。
6. **提出物の本文をAIに渡す際は、受講生の個人情報の取り扱いに注意する。** このツール自体は氏名・メールを返しませんが、提出本文に個人情報が含まれる場合があります。
7. **トークン漏洩の疑いがあれば即座にMoodleでトークンを削除する。**
