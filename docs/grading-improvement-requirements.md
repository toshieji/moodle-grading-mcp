## 1. 採点基準にない減点

### 1-1. 原因（コードで確認済み）

| # | 原因 | 箇所 | 起きたこと |
|---|---|---|---|
| R1 | **採点モデルに渡している採点表のタブが「表紙」だけ**。`RUBRIC_SHEET_GID=1694745353` は表紙で、課題ごとの減点項目のタブはモデルに渡っていない | `fetch_rubric_sheet_text()` / `deploy.sh` | モデルは、課題ごとの減点項目を見ないまま採点している |
| R2 | Moodle の評定ガイドからは、基準名と満点しか渡していない。減点条件が書かれた説明文を捨てている | `get_guide_criteria()` | 同上 |
| R3 | 詳しい採点規則として唯一渡している `ai-usage-log-rubric.md` が、**旧方式（v2.4：節目ごとに10点満点・内部修正6点＋外部追加4点・整形明示・節目平均）**のもの | `cloud/ai-usage-log-rubric.md` / `load_ai_usage_rubric()` | AI使用ログを旧方式で採点した。「整形明示がない −1」「節目平均 9.3」「URL未記載 −1」「自己申告とルーブリックの齟齬 −1」など |
| R4 | 厳しさの指示が、基準外の減点を促している。「平均的な提出物は6〜7割」「満点は原則つけない」「各基準で減点を最低1つ挙げる」「明確に満たしていると言い切れない限り該当とみなす」「記述が薄い・裏付けのない主張は減点」 | `_grade_once()` の system | 採点表にない観点（具体的な数値がない・原因分析が浅い・境界があいまい）で減点した |
| R5 | 合議の採点者B（実務妥当性）とC（教育的観点）に、採点表にない観点で採点させている | `PANEL` | 基準外の指摘が「根拠が具体的なら採用」のルールで最終案に残った |
| R6 | 減点の点数と合計を、コードで照合していない | `normalize_criteria_scores()` | 「減点3点」と書いたのに根拠は2点分しかない。「(A)1−(B)2」の (B) の説明が抜けている |

### 1-2. 要件

**入力（採点の根拠を1つにする）**
- F1. 課題ごとに、その課題の減点項目**だけ**をモデルに渡す。対応表は `assignid → 採点表タブ名` の形で持つ。対応表が見つからない課題は採点せず、「講師の採点が必要」として保留する
- F2. 採点の根拠は採点表スプレッドシートの課題タブに一本化する。Moodle 評定ガイドの説明文は照合用に使い、両者が食い違えば採点を保留してログに出す
- F3. `ai-usage-log-rubric.md`（v2.4 の節目方式）は採点の入力から外す。AI使用ログの採点は、採点表の「AIの使い方（別枠採点）」の減点項目だけで行う

**出力（減点は項目の選択にする）**
- F4. モデルが返すのは点数ではなく、**減点リスト**にする。各要素は `{項目ID, 件数, 根拠の引用（提出物から40字以内）, 引用元（ファイル名とページ・スライド番号）}` とする。項目IDはツール定義の enum で採点表の項目に限り、それ以外の値は受け付けない
- F5. 点数はコードで計算する：`満点 − Σ(項目の減点単価 × 件数)`。下限は0点。モデルが書いた合計は使わない
- F6. 採点表にない観点の指摘は、別欄の `改善提案`（点数に影響しない）に入れる。講評では「減点ではありません」と明記する

**プロンプト**
- F7. 厳しさの指示（R4）をやめ、次の1文にする：「採点表の減点項目に、提出物の引用で該当を立証できるときだけ減点する。立証できないときは減点しない。判断が割れるときは needs_human_review にする」
- F8. 合議は「照合役」を採点者、「実務・教育の観点」を改善提案の担当に分ける。改善提案の担当は点数を返さない。あるいは合議をやめて単独採点に戻し、時間と費用を1/4にする（F11 の検証結果で決める）

**検証（保存前にコードで止める）**
- F9. 減点リストに enum 外の項目・引用なし・単価の誤りがあれば、1回だけ再生成する。直らなければ保存せず保留する
- F10. 講評に書かれた点数と、保存する点数が一致することを確認する

**受け入れ条件**
- F11. 講師採点がある提出（今回の3名 × 事前課題1〜3）で再採点し、次を満たすこと
  - 採点表にない減点が0件（F4 の enum で構造的に保証。テストでも確認する）
  - 講師採点との差が、基準ごとに±1点以内の割合が80%以上
  - 講評の点数と保存した点数の不一致が0件

## 2. 講評が読みにくい

### 2-1. 原因

| # | 原因 | 箇所 |
|---|---|---|
| S1 | 上限超過で切り詰めるとき、HTML をすべて外して **1つの `<p>` に詰め直す**ので、改行・見出し・箇条書きが消える | `trim_feedback()` |
| S2 | 講評の構成をモデル任せにしていて、決まった型がない。「◎…△…」が1段落に続けて並ぶ | `_grade_once()` / `synthesize()` |
| S3 | 受講生向けの講評に、講師向けや内部の情報が混ざる。「3名の点差は19/16/22」「採点者C」「講師への確認点」「節目平均」「ルーブリック v2.4 §2」「内部修正6点」など | 同上 |
| S4 | 長すぎる。1課題で2,000〜4,000字あり、減点根拠（remark）は字数無制限。講師の講評は200〜600字 | `FEEDBACK_MAX_CHARS` / remark 無制限 |

### 2-2. 手本（講師の講評の型）

```
【内容：10点／10点】
◎ 評価できる点
・（1行1論点、2〜3個）
△ 減点理由（−1点）          ← 減点があるときだけ
・（どの記述が、どの項目に当たるか）
△ さらに良くするために
・（1〜2個）
※いずれも今回の採点基準上の減点事項ではありません。
```

### 2-3. 要件

**構成（型はコードで作る）**
- G1. モデルには講評の HTML を書かせない。構造化データ（評価できる点・減点理由・改善提案）を返させ、**HTML はコードが決まった型で組み立てる**
- G2. 型は講師の講評に合わせる。基準ごとに次の順で並べ、最後に合計の1行と、次への一言を1文添える
  - `【内容：X点／Y点】`
  - `◎ 評価できる点`（2〜3個）
  - `△ 減点理由（−N点）`（減点1件につき1行：項目名 −N点：根拠1文）
  - `△ さらに良くするために`（1〜2個、「減点ではありません」と明記）
- G3. HTML は `<p>` `<ul><li>` `<strong>` だけで組み、見出しと箇条書きの構造を残す。切り詰めが必要なときは箇条単位で落とし、構造は壊さない（S1 の廃止）

**文体**
- G4. です・ます調。1文は60字まで。1つの箇条に1つの論点
- G5. 受講生が知らない語は使わない。禁止語リストを持ち、コードで検査する：採点者A/B/C・合議・節目平均・内部修正点・外部追加点・整形明示・ルーブリック・v2.4・§・needs_human_review など
- G6. 提出物からの引用は「」でくくり、40字まで

**受講生向けと講師向けを分ける**
- G7. 受講生向け（Moodle のフィードバック）には、点数・評価できる点・減点理由・改善提案だけを入れる
- G8. 講師向け（判断に迷った点・3名の点のばらつき・減点を見送った点）は、フィードバックの冒頭の「❓ 講師の確認をお願いします」枠にだけ書く。この枠は公開前に講師が削除する。あわせて、採点表の「講師AI採点レビュー」欄に転記できる形で、ジョブのログにも出す
- G9. 評定ガイドの基準ごとのコメント（remark）は、公開すると受講生に見えるので、受講生向けと同じ文体の短い要約（200字まで）にする

**長さ**
- G10. 受講生向けの本文は、1課題あたり400〜800字を目安にする（修了レポートは1,500字まで）。上限を超えたら、改善提案 → 評価できる点の順に箇条を減らす。先日上げた本番ジョブの上限（4,000字）は、G1〜G3 を入れた時点で戻す

**受け入れ条件**
- G11. 自動検査（テスト）
  - 型の見出しがすべてある
  - 禁止語が0件
  - 1文60字以内
  - 本文の字数が範囲内
  - 講評の点数と保存した点数が一致する
- G12. 講師が5件を読み、「そのまま公開できる」または「軽微な修正で公開できる」が4件以上

## 3. 進め方（案）

1. F1〜F3（入力の是正）とG1〜G3（型の組み立て）を先に入れる。基準外の減点と読みにくさの原因の大半はここにある
2. F11 の再採点で、合議を続けるか単独採点に戻すか（F8）を決める
3. 本番への反映は、今回と同じ手順で行う（イメージを作り、江尻が切り替えて実行する）

## 4. 測っていないこと

- 講師レビューがあるのは3名の事前課題1だけ。事前課題2・3の講師採点は空欄なので、F11 の「講師との差」は、事前課題1の6件でしか測れない
- 講評の読みやすさ（G12）は講師の判断による。自動検査（G11）は必要条件にすぎない
